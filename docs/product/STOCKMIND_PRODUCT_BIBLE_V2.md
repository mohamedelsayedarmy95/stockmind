# STOCKMIND — PRODUCT BIBLE v2 (الرؤية المصحّحة والمبنية على الأدلة)

> **الحالة:** Series 08 — توثيق واستراتيجية. v2 بيحل محل أي وصف في Product Bible v1.0 ممّا يتعارض مع الكود أو مع الأدلة.
> **قاعدة القراءة:** كل ما يخص "اللي موجود" مرتبط بـ `STOCKMIND_CODE_TO_CAPABILITY_GAP_MATRIX.md` (GM). كل ما يخص "اللي المفروض يتبني" **مقترح** مرتبط بالـ ADR/الـ roadmap. **أرقام السوق/الإيراد/المنافسين/الامتثال/دقة الـ AI/توقعات 36 شهراً = فرضيات غير مُثبتة (§8).**
> **المبدأ:** الهدف مش أكبر عدد ميزات؛ الهدف برنامج **فعّال ومتماسك وآمن وشغّال فعلاً**: كل عنصر UI = عملية مدعومة ومصرّح بها ومختبَرة. لا ميزات ديكورية، ولا تحليلات وهمية، ولا حالة مزامنة مضلّلة، ولا ادّعاء أمان/امتثال بدون دليل.

## 2. الرؤية المصحّحة

StockMind بيتطور من **تطبيق مخزون** لـ **منصة ثقة وعمليات للمخازن (Warehouse Operations & Trust Platform)** موجّهة للموبايل، بتجمع: **سلامة دفتر المخزون** + **مساءلة الموظفين بهويات حقيقية** + **صلاحيات دقيقة بنطاق** + **تنفيذ أوفلاين موثوق** + **موافقات مشروطة** + **عهدة تحويل** + **رؤية إدارية صادقة** + **تجربة عربية/إنجليزية ممتازة**. الذكاء والرؤية الحاسوبية والتكاملات بتيجي **بعد** ما تبقى البيانات والثقة موجودة.

## 3. الأعمدة السبعة — بعد التصحيح

> **لا شرط إن العمود يكتمل قبل ما شريحة معتمدة عليه تبدأ.** بنحدد الاعتماد التقني الفعلي (الـ roadmap §1).

| العمود | الوضع الحالي | ما يُبنى أولاً (شريحة) | يتأجل |
|---|---|---|---|
| **Ledger** | قوي: ترتيب، idempotency، مصالحة، generation (GM:L1–L11) | S3 مساءلة (recipient/purpose/ref/UOM) + domain_events | double-entry كامل، تقييم مالي |
| **Governance** | أدوار ثابتة + منح مخازن (GM:C4–C8) | S0/S1/S2 (خصوصية، دورة حياة، قدرات) ثم S4 موافقات | ABAC/محرك خارجي، تفويضات معقدة |
| **Custody** | تحويل فوري فقط (GM:L3) | S6 تحويل بعهدة (بعد S2–S4) | ناقل خارجي، شحن |
| **Execution** | الأقوى: outbox، sync، تعويض، باركود محلي | تحسينات UX (J1/J2) مع الصلاحيات | مهام معقدة (picking waves) |
| **Intelligence** | `/ai/ask` و`/ai/reorder` (UNVERIFIED الدقة) | تحليلات صادقة بعد S3 | forecasting/استدلال AI — بدقة مقاسة |
| **Vision** | مسح باركود محلي (GM:M4) | — | OCR فواتير، عدّ بالصور، shelf viz = spikes قابلة للإلغاء |
| **Ecosystem** | لا شيء (GM:E1) | S9: تصدير CSV | ERP/e-commerce/محاسبة، API/webhooks، منصة |

## 5. العميل المستهدف الأولي (فرضية للتحقق بمقابلات)

**ICP مقترح:** نشاط **توزيع/تجارة سلع سريعة الدوران (FMCG)** مملوك لصاحبه، **2–5 مخازن/نقاط تخزين**، **5–30 موظفاً**، بيشتغل على Excel/ورق/واتساب، وألمه الأساسي: **مساءلة الصرف والفروقات بين المخازن وبين الموظفين**. **ليه:** ميزة StockMind الأقوى (هوية الموظف + أوفلاين + سلامة الدفتر + عهدة التحويل لاحقاً) بتلمس الألم ده مباشرة وبعمق WMS أقل من قطع الغيار (مواقع/serials). قطع الغيار تجربة تانية بعد S7. **ما اتأكدش:** مفيش مقابلات ولا عملاء ولا التزامات؛ الاختيار فرضية.

### 5.1 ثلاث تجارب تحقق مع شركاء تصميم (محدودة)
> **قيد صريح:** الإنتاج NO-GO والوضع الأونلاين dev-preview؛ فالتجارب الأولى **ما بتحتاجش نسخة إنتاج**.

| # | التجربة | الطريقة | المقياس (فرضية) | ما تثبته |
|---|---|---|---|---|
| E1 | **إعادة تشغيل حركات حقيقية** | 30 يوم سجل حركات (CSV مُجهَّل) من 2–3 شركاء يتعمل replay على نموذج الحركة المقترح في sandbox | % الحركات اللي تتسجل بدون نص حر؛ الحقول المفقودة (مستلم/غرض/مرجع) | هل مخطط الحركة (الـ governance spec §2) كافٍ |
| E2 | **معايرة عتبات الموافقة** | محاكاة قواعد (كمية/قيمة/نوع) على نفس السجلات | % العمليات اللي هتحتاج موافقة وحمل المعتمد (هدف فرضي ≤ 10% و≤ X قرار/يوم لكل معتمد) | هل الافتراضي "مش على كل سحب" صح، وما العتبات |
| E3 | **اختبار استخدام للموظفين** | تدفقات J1/J2/J4 على build تجريبي مع 5–8 موظفين | زمن المهمة، لمسات، فهم "محفوظ على الجهاز ≠ مؤكد" | الأهداف في الـ UX blueprint §2/§9 |
**بوابة الـ pilot الحقيقي** (بعدها): S0–S2 + Milestone R + قرار release line + موافقة Director على بيئة الـ pilot.

### 5.2 أصغر شريحة تجارية ذات قيمة
**"Accountable team inventory":** مخزون مشترك بين موظفين بهويات منفصلة + نطاق مخازن لكل موظف + استلام/صرف أوفلاين موثوق + تاريخ "مين عمل إيه ومتى" + **تكلفة مخفية عمّن لا يحق له** + سلامة بعد الأعطال (S1/S2 من Series 07). = **S0 + S1 + S2 + (S3 الأساسي) + Milestone R**. **بدون** موافقات ولا عهدة تحويل (دي طبقة Business).
**قيمة للمالك:** يعرف مين خرّج إيه ويشيل صلاحية موظف سابق فوراً. **ما لا يعد به:** منع كل الفروقات، ولا رؤية لحظية لأجهزة غير متصلة، ولا امتثال.

## 7. مؤشرات الأداء (تعريف القياس؛ العتبات فرضيات)

| المؤشر | التعريف (بسط/مقام، المصدر، النافذة) |
|---|---|
| **Activation** | مالك دعا ≥1 موظف **و** الموظف عمل ≥1 حركة **مؤكدة** خلال 7 أيام من إنشاء الشركة (events) |
| **Confirmed latency** | وقت من التقاط العملية على الجهاز لحد تأكيد السيرفر، p50/p95 (مقاس على الـ outbox) — الـ cold start المقاس ~42 ث بيؤثر |
| **Review rate** | عدد عمليات NEEDS_REVIEW / 1000 عملية (أقل = أفضل؛ مؤشر استقرار المزامنة والاسترداد) |
| **Straight-through share** | عمليات بدون موافقة / كل العمليات (يوازن العبء) |
| **Approval latency** | وقت الطلب → القرار p50/p90؛ نسبة EXPIRED |
| **Discrepancy rate** | حالات فرق / 1000 سطر تحويل أو جرد |
| **Revocation latency** | من تعليق عضو لأول طلب مرفوض (الهدف ≤ طلب واحد) |
| **Privacy incidents** | حالات ظهور تكلفة لغير مخوّل (الهدف صفر؛ يُقاس باختبارات آلية + مراجعة) |
| **Sync health** | % polls ناجحة، p95 زمن `/stock/changes`، معدل resets غير المتوقعة |
| **Design-partner retention** | فرق نشطة أسبوعياً بعد 8 أسابيع / الفرق اللي بدأت |
| **Support load** | تذاكر لكل فريق نشط/أسبوع |
(**لا يُدّعى رقم قبل وجود قياس فعلي.**)

## 8. سجل الفرضيات (غير مُثبتة — مش حقائق)

H1 حجم سوق FMCG/قطع الغيار في المنطقة · H2 استعداد الدفع وبنية الأسعار · H3 فجوات المنافسين · H4 الحاجة لـ pharma وشروطها · H5 دقة أي AI/forecasting · H6 الامتثال/الشهادات المطلوبة · H7 الإقامة الجغرافية · H8 إسقاط 36 شهراً · H9 أن الموافقات تُستخدم فعلاً (E2) · H10 أن مالك صغير يقبل تعقيد السياسات · H11 أن الموظفين يتبنّوا الـ scan-first · H12 تكلفة الـ infra عند الحجم (Render/Neon/FCM: غير مقاسة).
**ما يحتاج مقابلات مش كود:** أدوار فعلية، حجم الحركة اليومي، من يوافق فعلاً، ما الذي يُعتبر "حساس"، هل التحويل بين مخازن بعهدة فعلاً، هل المخازن متصلة، اللغة/الأرقام، عتبات الدفع.

## 9. اعتبارات التكلفة والاختبار
- **تشغيل:** Render مجاني بينام (cold start ~42 ث مقاس)، Neon مجاني (قيوده غير محقّقة)، FCM مجاني، لا Redis مُجرَّب. أي **instance دائم / SSE / مراقبة / تخزين مرفقات** = تكلفة جديدة **غير مقدّرة** وبتحتاج تفويضاً.
- **اختبار أجهزة:** جهاز Huawei واحد (Android 10) متاح؛ **iOS لم يُبنَ أبداً** (يحتاج macOS/EAS)؛ اختبار جهازين = متطلب من S4 (موافقات) فصاعداً.
- **الجودة:** Jest مابيغطيش UI (درس Series 07)؛ كل شاشة جديدة تحتاج اختبار جهاز أو component tests.
